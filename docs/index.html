01

Keep behavior separate from facts.

A template defines how a simulated buyer behaves. A deal contains what is actually known about an opportunity. A practice combines them without disguising assumptions as customer history.

Reusable template

Call type, buyer archetype, objection territory, difficulty, opening, success condition, and scorecard. Share it without exposing customer data.

Optional deal

Seller, prospect, stage, price, known objections, competitors, history, and next-meeting objective. Every fact retains its source.

Immutable practice

A versioned combination of template, optional deal, and explicit overrides. Build hashes make stale or changed inputs visible.

Evidence-linked review

Criterion scores, objections, explanations, alternatives, and confidence—all linked to valid transcript turn IDs.

02

Install and initialize.

Tommy emits one JSON envelope per command, so both agents and shell workflows can inspect state without scraping terminal decoration.

Shell · installation
pip install -e '.[edsl]'
tommy init demo --name "Sales practice"
cd demo
tommy guide
tommy next
Agent-first by designA human can use every command directly, but the intended experience is to tell an agent what call you need to prepare for. The agent turns notes into small, inspectable artifacts and explains consequential assumptions.

Add the reusable scorecard and template

Shell · reusable inputs
tommy scorecard add ../examples/enterprise-pricing/scorecard.json
tommy template add ../examples/enterprise-pricing/template.json

Optionally attach a real deal

Shell · deal-specific context
tommy deal add ../examples/enterprise-pricing/deal.json

tommy practice prepare \
  --template enterprise-pricing \
  --deal acme-research \
  --id jordan-pricing

For generic training, omit --deal. You can still override the buyer role, mode, difficulty, duration, opening, or focus for one practice.

Shell · generic practice
tommy practice prepare \
  --template enterprise-pricing \
  --id generic-cfo-pricing \
  --buyer-role "Chief Financial Officer" \
  --focus budget-math \
  --mode voice
03

Build, inspect, and launch.

Building creates a native EDSL Survey and buyer guide. Previewing is read-only. Launching is a deliberate external action that creates a private Expected Parrot respondent study.

Shell · build and preview
tommy practice build --practice jordan-pricing
tommy practice preview --practice jordan-pricing

✓ Safe inspection

practice build creates local artifacts. practice preview returns a preview URL without creating a respondent study.

⚡ External boundary

Review the buyer, opening, pressure points, and win condition first. Deployment requires an explicit confirmation flag.

Shell · launch after approval
tommy practice deploy \
  --practice jordan-pricing \
  --confirm

The resulting JSON contains the private respondent URL and deployment record. Share the URL with the rep completing the roleplay.

04

Preserve every attempt.

Each completed call becomes a distinct attempt. Earlier transcripts and reviews are never silently overwritten, making improvement across repeated practice measurable.

Shell · import transcript
tommy attempt import \
  --practice jordan-pricing \
  --transcript transcript.json \
  --rep "Alex Rivera" \
  --id alex-round-1
attempt.json

Rep, buyer, practice hash, provenance, status, and normalized timestamped turns.

review.json

Canonical structured evaluation with criterion scores and validated transcript evidence.

report.html

Portable coaching view generated from the attempt and review; it is not the source of truth.

05

Review the evidence, not just the score.

Tommy rejects missing criteria, out-of-range scores, and evidence citations pointing to nonexistent turns. The report makes the chain from observation to interpretation to suggestion visible.

Jordan · Walk me through how this price pays for itself.
Alex · It helps teams make better decisions much faster.
Jordan · That is a principle, not budget math.
Alex · Which part of your research queue causes the most delay?
80

Evidence-linked coaching

Lead with the buyer's operational constraint instead of an abstract promise. The discovery recovery was strong; the close still needed an owned follow-up date.

● Discovery 3/3
● Objection handling 3/3
● Concrete next step 1/2
Shell · register and render
tommy review register \
  --attempt alex-round-1 \
  --file review.json

tommy report --attempt alex-round-1
What the HTML report containsBuyer and seller transcript styling, overall and grouped scores, strengths, recommendations, expandable criteria, objection resolution, evaluator confidence, and links that scroll to and highlight exact transcript turns.
06

Let the agent manage the machinery.

The agent should ask what conversation you need to prepare for, normalize your notes, reuse suitable templates, surface its assumptions, and stop for approval before deployment.

Prompt · minimal starting point
You are operating Tommy. Run `tommy guide` and `tommy next`, inspect existing
artifacts, and help me prepare for this sales conversation:

[paste deal notes or describe the generic skill to practice]

Keep supplied facts separate from inference. Prepare one focused practice,
show me the buyer design before deployment, and do not cross an external
boundary without my approval. After the attempt, ground every review claim
in valid transcript turn IDs and generate the standalone HTML report.
